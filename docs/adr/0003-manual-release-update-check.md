# ADR 0003：手动检查 GitHub Release 更新

- 状态：已接受
- 日期：2026-09-02

## 背景

应用通过 GitHub Release 公开分发。当前发布不包含平台签名和公证，因此不能把下载的安装包当作可信更新载荷在后台静默执行。同时，用户需要在设置页主动确认是否存在新版本。

## 决策

- 更新检查只在用户打开设置页并点击“检查更新”时执行。
- Electron Main 进程请求固定的 GitHub Releases API，Renderer 不直接访问网络。
- 只接受严格的 `vX.X.X` 稳定版本，并拒绝相同或更低版本。
- Preload 只暴露版本读取、更新检查和打开固定 Release 页面三个最小 API。
- 发现新版本后，用户点击确认按钮，由系统打开固定的 GitHub Release 下载页面；应用不静默下载、执行或替换自身。
- 检查失败只返回有限错误代码，Renderer 使用 i18next 展示用户可见反馈；技术细节不得暴露给 Renderer，由 Main 日志负责。

## 结果

更新检查不需要新增更新服务器，也不改变现有 Forge 打包方式。GitHub API 限流、网络中断或 Release 数据异常不会阻止应用启动。未来若要实现真正的自动安装，需要另行评估平台签名、更新元数据、资产完整性验证、回滚和跨平台更新测试，不能直接把本 ADR 的手动下载流程升级为静默更新。
