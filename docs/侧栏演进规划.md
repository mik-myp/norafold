# Norafold 侧栏演进规划

本文档记录 Norafold 侧栏的当前基线、产品信息架构和后续升级路径。后续新增工作区、会话、知识库、工作流、MCP 等功能时，先根据本文档判断是否需要升级侧栏结构，再修改实现。

## 设计目标

Norafold 是面向普通用户和开发者的本地优先 AI 工作台。侧栏需要同时支持：

- 高频入口：工作台、会话、知识库、工作流和 MCP。
- 资源导航：会话列表、知识库列表、工作流列表、MCP 服务和收藏项。
- 桌面效率：Electron 窗口中可折叠为图标，为对话、代码和 React Flow 画布保留空间。
- 渐进复杂度：第一版保持易懂，功能变多后再引入上下文列表和多层侧栏。
- 移动端可用：小屏幕使用抽屉式侧栏，不依赖桌面端的双栏布局。

## 官方模板对比

官方示例：[shadcn/ui Sidebar Blocks](https://ui.shadcn.com/blocks/sidebar)

| 模板         | 结构与交互                             | 适合场景                   | Norafold 判断                                  |
| ------------ | -------------------------------------- | -------------------------- | ---------------------------------------------- |
| `sidebar-01` | 按 section 分组的简单导航              | 文档、知识库、简单后台     | 可作为最小 MVP，但扩展性有限                   |
| `sidebar-02` | section 可折叠                         | 导航分组较多的后台         | 可用于设置等次要分组，不隐藏核心入口           |
| `sidebar-03` | 一级项下始终显示子菜单                 | 层级固定的功能模块         | 适合知识库或工作流内部导航                     |
| `sidebar-04` | 浮动侧栏，带子菜单                     | 展示型 Dashboard           | 不作为主布局，浮动容器会减少工作区空间         |
| `sidebar-05` | 子菜单可折叠                           | 层级较深的资源管理         | 后期可用于工作流、MCP 和设置                   |
| `sidebar-06` | 子菜单通过 Dropdown 展示               | 极简、紧凑导航             | 不用于核心入口，功能发现性较差                 |
| `sidebar-07` | 侧栏可折叠为图标                       | SaaS、桌面工作台、Electron | 当前最重要的交互模式                           |
| `sidebar-08` | inset 主内容、项目区、次级导航和用户区 | 通用应用壳                 | 当前组件基础，导航内容使用 Norafold 自己的数据 |
| `sidebar-09` | 左侧图标栏 + 当前模块上下文列表        | 邮件、会话、文件、知识库   | 后期复杂工作台的目标结构                       |
| `sidebar-10` | 收藏、工作区、页面操作 Popover         | Notion 类个人工作台        | 后期吸收其收藏、工作区和导入导出模式           |

这些模板是布局示例，不是需要全部安装的组件。它们会共享 `ui/sidebar.tsx`，混合安装会造成文件覆盖和演示代码冗余。实现时只提取需要的布局和交互模式。

## 当前基线

当前实现采用：

```text
sidebar-08 的基础组件
+ sidebar-07 的 icon collapse 交互
+ TanStack Router 的 Link 和路由匹配
+ Norafold 自定义导航数据
```

当前代码位置：

- [app-sidebar.tsx](../src/components/layouts/app-sidebar.tsx)：品牌区、主导航和侧栏容器。
- [nav-main.tsx](../src/components/navigation/nav-main.tsx)：导航项、激活状态和移动端抽屉关闭。
- [app-shell.tsx](../src/components/layouts/app-shell.tsx)：`SidebarProvider`、面包屑和主内容区。
- [sidebar.tsx](../src/components/ui/sidebar.tsx)：shadcn Sidebar 基础组件。

当前导航保持克制：

```text
工作台
本地知识库
```

此阶段不照搬 `sidebar-08` 的 Acme、Projects、Support 等演示数据，也不把主内容强制做成 inset 卡片。对话和 React Flow 画布需要尽可能大的连续工作区。

## 阶段一：MVP 工作台

### 目标

在不增加导航层级的情况下，建立稳定的主入口和 Electron 友好的布局。

### 推荐导航

```text
工作区
├── 工作台
├── 会话
├── 本地知识库
├── 工作流
└── MCP

底部
├── 设置
└── 帮助
```

### 实施规则

- 保持 `Sidebar collapsible="icon"`，折叠后每个入口必须有 tooltip。
- 使用 TanStack Router 的 `Link`，禁止模板中的 `href="#"`。
- 激活状态由当前路由计算，不在侧栏内部复制一套页面状态。
- 核心入口默认可见；只折叠分组，不隐藏核心模块。
- 移动端导航使用 Drawer/Sheet，点击路由后关闭抽屉。
- 主内容区默认贴边布局；只有确实需要内容框架时才使用 `variant="inset"`。

### 完成条件

- 桌面端可以在展开和图标模式间切换。
- `/`、`/knowledge` 等路由激活状态正确。
- 移动端打开抽屉、切换路由、关闭抽屉的流程完整。
- 侧栏折叠后不影响主内容宽度、对话输入框和 React Flow 画布。

## 阶段二：资源列表和工作区

当会话、知识库、工作流或 MCP 产生真实的用户资源后，引入 `sidebar-10` 的信息组织方式，但不必直接复制其完整 UI。

### 推荐结构

```text
主导航
├── 搜索
├── 工作台
├── 会话
├── 本地知识库
├── 工作流
└── MCP

收藏
├── 收藏会话
├── 收藏知识库
└── 收藏工作流

最近使用

工作区
├── 个人空间
└── 项目空间
```

### 可吸收的 sidebar-10 模式

- 收藏和最近使用列表。
- 工作区/项目切换。
- 资源的复制、归档、移动、导入和导出。
- 页面或工作流右上角的更多操作 Popover。
- 资源列表过长时配合虚拟滚动和搜索。

### 数据边界

- 侧栏只负责导航和选择，不直接读写 SQLite。
- 资源列表通过 TanStack Query 调用 Electron IPC。
- 选中的资源 ID 进入 TanStack Router 参数或搜索参数。
- 临时展开状态、选中节点和草稿放在 UI store，不写入业务表。
- 收藏、排序、归档等用户偏好才持久化到 SQLite。

### 进入阶段二的触发条件

满足以下任意两项即可评估升级：

- 单个模块稳定拥有超过 5 个用户资源。
- 用户需要频繁在最近使用和收藏之间切换。
- 侧栏出现超过 8 个一级入口。
- 用户开始管理多个项目或工作区。
- 用户需要从侧栏直接创建、复制、归档资源。

## 阶段三：双层上下文侧栏

当用户频繁在“模块”和“模块内部资源”之间切换时，采用 `sidebar-09` 的双层结构。

```text
[模块图标栏] [当前模块资源栏] [主工作区] [可选右侧面板]
```

### 模块示例

```text
对话       最近会话 / 收藏 / 归档
知识库     我的知识库 / 文档 / 分块 / 检索测试
工作流     我的工作流 / 模板 / 运行历史
MCP        已连接服务 / 工具 / 调用记录
设置       模型 / 权限 / 存储 / 快捷键
```

### 适用场景

- 长对话需要保留会话列表，同时保持对话区域宽度。
- 知识库需要在库、文档和检索结果之间快速切换。
- React Flow 编辑器需要独立的工作流列表和节点配置区域。
- MCP 调试需要同时查看服务列表、工具详情和调用日志。

### 复杂度约束

- 模块选择必须可由 URL 表达，避免刷新后丢失上下文。
- 当前资源必须有稳定的 ID，不能只依赖数组下标或本地临时状态。
- 桌面端显示双层结构，移动端退化为“模块抽屉 -> 资源抽屉 -> 内容”。
- 中间资源栏支持搜索、虚拟滚动和空状态。
- 右侧详情面板按模块按需出现，不默认占用主工作区。

### 进入阶段三的触发条件

- 至少两个模块同时拥有独立资源列表。
- 用户在同一任务中需要反复切换模块和资源。
- 单层侧栏已经出现明显的滚动、折叠或定位困难。
- 资源列表和主内容需要同时可见才能完成核心操作。

## 路由与状态约定

侧栏演进不能改变领域层的职责边界：

```text
TanStack Router
  └── 当前模块、资源 ID、筛选条件和可分享 URL

TanStack Query
  └── IPC 查询、缓存、失效和刷新

TanStack Store
  └── 侧栏展开状态、面板布局、节点选择和未提交草稿

SQLite
  └── 会话、文档、工作流、MCP 配置、收藏、排序和运行记录
```

不要让 `assistant-ui`、LangGraph 或 TanStack AI 的内部状态直接成为侧栏数据模型。侧栏依赖 Norafold 自己的领域数据和事件协议。

## 迁移顺序

1. 继续维护当前 `sidebar-08 + collapsible="icon"` 基线。
2. 增加会话、工作流、MCP 等一级路由，但先不引入第二层侧栏。
3. 资源真实存在后，加入搜索、收藏、最近使用和工作区切换。
4. 将资源操作抽象为通用 Popover 菜单，吸收 `sidebar-10` 的模式。
5. 满足阶段三触发条件后，再将模块导航和资源导航拆成 `sidebar-09` 的双层结构。
6. 每次迁移都先保证桌面端、移动端、路由刷新和键盘操作可用，再扩展视觉细节。

## 明确不采用的做法

- 不同时安装并维护 `sidebar-01` 到 `sidebar-10` 的完整示例。
- 不使用 `href="#"` 作为真实导航。
- 不把核心功能全部藏进 Dropdown。
- 不在侧栏组件内部直接实现 SQLite、RAG 或 LangGraph 业务逻辑。
- 不为了追求模板还原而牺牲对话、代码和画布的可用空间。
- 不在阶段一提前引入双层侧栏、复杂工作区和大量模拟资源。

## 决策摘要

```text
现在：sidebar-08 基础组件 + sidebar-07 图标折叠
资源变多：吸收 sidebar-10 的收藏、工作区和 Popover 操作
工作台复杂：升级为 sidebar-09 双层上下文侧栏
```

后续任何侧栏改动都应说明：当前所处阶段、触发了哪项升级条件、是否影响路由和移动端行为，以及是否需要迁移已有用户的布局偏好。
