## 产品定位

Norafold 是一个面向普通用户和开发者的本地优先 AI 工作台，核心能力包括：

- AI 对话、多模态消息和流式输出
- 本地文件读取、编辑和生成
- 代码编写、执行、终端和预览
- 本地知识库与 RAG
- MCP 服务发现、授权和工具调用
- ReAct / Agent 执行
- 基于 React Flow 的可视化工作流
- 默认模板、基于模板修改、完全自定义创建
- 后续接入 Electron，默认将数据保存在本地

## 总体架构

```text
React + Vite+
├── assistant-ui：主要 AI 交互界面
├── AI Elements：补充缺失的展示组件
├── React Flow：工作流编辑器
└── TanStack 系列：路由、数据、表单、表格和 UI 状态
              │
              ▼
Norafold 领域层与事件协议
              │
              ▼ Electron IPC
Electron Worker / Utility Process
├── LangChain：模型、Prompt、RAG、检索器和工具封装
├── LangGraph：Agent 与工作流执行引擎
├── MCP SDK：MCP 连接、权限和调用
└── SQLite：本地持久化与向量检索
```

## AI 技术边界

- `LangChain`：模型适配、Prompt、文档加载与切分、Embedding、Retriever、RAG、Tool。
- `LangGraph`：Agent 状态图、工作流执行、审批、中断、重试、超时、取消、Checkpoint 和恢复。
- `@modelcontextprotocol/sdk`：MCP 服务连接、工具发现、参数校验、权限控制和调用记录。
- `React Flow`：只负责编辑和展示工作流，不负责实际执行。
- Norafold 将 React Flow JSON 编译成 LangGraph 图后，在 Electron 后台进程执行。

LangGraph 是唯一的复杂 Agent/工作流运行时，避免 TanStack AI、LangChain Agent 和 LangGraph 同时控制工具循环。

## AI UI 选择

主组件库选择 `assistant-ui`：

- 对 LangGraph、LangChain、AG-UI 和自定义 Runtime 支持更成熟
- 负责会话线程、流式消息、工具调用、审批、中断恢复和生成式 UI
- 更适合作为 Norafold 的主要聊天 Runtime

`AI Elements` 作为辅助组件来源：

- assistant-ui 已有的能力优先使用 assistant-ui
- assistant-ui 缺少而 AI Elements 提供时，复制并适配该组件
- 适合补充代码块、终端、文件树、网页预览、任务、来源和 React Flow Canvas
- 只使用展示组件，不引入 AI SDK 的 `useChat` 作为第二套聊天 Runtime

建议 UI 基础层选择 `shadcn/ui + Base UI`，新组件尽量遵循同一套交互和视觉规范。

## TanStack AI 定位

TanStack AI 暂不作为核心运行时。它不能直接提升模型推理、RAG 命中率或 Agent 能力，主要价值在：

- 流式传输
- 类型安全的 Tool
- 审批状态
- 自定义 Connection Adapter
- 结构化输出
- 客户端消息状态

先完成 LangChain/LangGraph 主链路。只有当 TanStack AI 能明显减少 Electron IPC、流式事件或客户端状态代码时，再局部接入。

不要同时运行：

```text
assistant-ui Runtime
@tanstack/ai-react useChat
@ai-sdk/react useChat
```

聊天状态运行时只保留一套，目前选择 assistant-ui。

## TanStack 前端体系

- `@tanstack/react-router`：工作区、会话、知识库、工作流、MCP 和设置路由
- `@tanstack/react-query`：IPC 查询、缓存、失效和刷新
- `@tanstack/store`：布局、选中节点、草稿等临时 UI 状态
- `@tanstack/react-form`：模型、MCP、权限和节点配置表单
- `@tanstack/react-table`：文档、任务、审批、审计和运行历史
- `@tanstack/react-virtual`：长对话、日志、分块和流式记录
- `@tanstack/pacer`：高频事件和文件变化节流
- `@tanstack/react-hotkeys`：快捷键
- `@tanstack/react-charts`：Token、延迟、错误率和 RAG 指标

这些工具只管理前端交互和缓存，SQLite 才是本地数据的最终来源。

## 本地数据方案

当前方案合理：

```text
SQLite
+ better-sqlite3
+ Drizzle ORM
+ Drizzle migrations
+ SQLite FTS5
+ sqlite-vec
```

职责划分：

- SQLite：会话、消息、文档、工作流、MCP 配置、权限、运行记录
- FTS5：关键词和全文检索
- `sqlite-vec`：Embedding 向量检索
- Drizzle：结构化数据访问和迁移
- 文件系统：原始文档、附件、模型文件和大型 Artifact
- 数据库只保存路径、元数据、索引和关联关系

数据库、RAG、MCP 和工作流执行应放在 Electron 主进程之外的 Worker 或 Utility Process，避免阻塞 UI。

## 稳定事件协议

定义 Norafold 自己的事件模型：

```text
LangGraph Event
      ↓
NorafoldRunEvent
├── Electron IPC
├── SQLite 运行记录
├── assistant-ui Adapter
└── AI Elements Renderer
```

不要让 LangGraph、assistant-ui、TanStack AI 或 AI SDK 的内部类型直接进入数据库和领域模型。这样未来替换 UI、增加移动端或远程执行都不会影响核心数据结构。

## 最终技术方向

```text
核心：
LangChain + LangGraph + MCP SDK

执行与存储：
Electron Worker + SQLite + Drizzle + FTS5 + sqlite-vec

前端：
React + Vite+ + TanStack 系列 + React Flow

AI UI：
assistant-ui 为主
AI Elements 按需补充
shadcn/ui + Base UI 作为基础组件系统

条件接入：
TanStack AI
```

整体原则是：LangChain 系列负责 AI 能力，LangGraph 唯一负责执行，Norafold 自己掌握数据和事件协议，UI 组件库只负责交互与展示。
